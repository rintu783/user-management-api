# User Management API

A simple REST API for managing users (create, list, get, update, delete), built with FastAPI and PostgreSQL. It uses raw SQL through psycopg2, with no ORM. Interactive documentation and testing are available through Swagger UI.

## Features

- Create a user
- List all users
- Get a single user by id
- Update a user
- Delete a user
- Input validation (422) and clear not-found errors (404)

## Tech Stack

- Python 3.10+
- FastAPI
- PostgreSQL
- psycopg2 (raw SQL, no ORM)
- python-dotenv
- Uvicorn

## Prerequisites

- Python 3.10 or newer
- PostgreSQL installed and running
- git
- Linux with `sudo` access (the database setup script uses `sudo -u postgres`)

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/rintu783/user-management-api.git
cd user-management-api
```

### 2. Create and activate a virtual environment

```bash
python3 -m venv venv
source venv/bin/activate
```

Your terminal prompt should now start with `(venv)`. Run the `source` command again in every new terminal.

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Set up the database

```bash
python setup_db.py
```

The script asks for a database name, a database user and a password. It then:

1. Writes your `.env` file with the connection settings
2. Creates the PostgreSQL user and database (if they don't exist)
3. Creates the `users` table from `app/schema.sql`

You may be asked for your system password, because the script runs `sudo -u postgres`.

The password cannot be empty or contain spaces, quotes, `#` or backslashes.

If you prefer to create `.env` yourself, copy the template and fill in your values:

```bash
cp .env.example .env
```

```
DB_HOST=localhost
DB_NAME=user_management
DB_USER=user_api
DB_PASSWORD=your_password
```

### 5. Run the app

```bash
uvicorn app.main:app --reload
```

The API runs at http://127.0.0.1:8000. Stop it with `Ctrl+C`.

## API Endpoints

| Method | Endpoint | Description | Success | Errors |
|---|---|---|---|---|
| POST | /users | Create a user | 201 | 422 |
| GET | /users | List all users | 200 | none |
| GET | /users/{user_id} | Get one user | 200 | 404 |
| PUT | /users/{user_id} | Update a user | 200 | 404, 422 |
| DELETE | /users/{user_id} | Delete a user | 204 | 404 |

## User Fields

| Field | Type | Notes |
|---|---|---|
| id | integer | generated by the database, not sent by the client |
| name | text | up to 100 characters |
| gender | text | up to 20 characters |
| age | integer | entered manually, not calculated from `dob` |
| dob | date | format `YYYY-MM-DD`, for example `1999-12-05` |
| address | text | |
| blood_group | text | up to 5 characters, for example `O+` |
| time_zone | text | for example `Asia/Kolkata` |

## Example Requests and Responses

### Create user: POST /users

Request body:

```json
{
  "name": "Rintu Das",
  "gender": "male",
  "age": 26,
  "dob": "1999-12-05",
  "address": "12 MG Road, Kolkata",
  "blood_group": "O+",
  "time_zone": "Asia/Kolkata"
}
```

Response (201):

```json
{
  "id": 1,
  "name": "Rintu Das",
  "gender": "male",
  "age": 26,
  "dob": "1999-12-05",
  "address": "12 MG Road, Kolkata",
  "blood_group": "O+",
  "time_zone": "Asia/Kolkata"
}
```

### List users: GET /users

Response (200):

```json
[
  {
    "id": 1,
    "name": "Rintu Das",
    "gender": "male",
    "age": 26,
    "dob": "1999-12-05",
    "address": "12 MG Road, Kolkata",
    "blood_group": "O+",
    "time_zone": "Asia/Kolkata"
  }
]
```

### Get one user: GET /users/1

Response (200): the user object, in the same format as above.

### Update user: PUT /users/1

Send all fields in the body (same format as create). Response (200): the updated user object.

### Delete user: DELETE /users/1

Response (204): empty body.

### Not found: GET, PUT or DELETE /users/9999

Response (404):

```json
{ "detail": "User 9999 not found" }
```

### Invalid body: POST /users with `"age": "abc"`

Response (422): a JSON body listing the invalid fields and the reasons.

## Testing with Swagger UI

1. Start the app and open http://127.0.0.1:8000/docs.
2. Click an endpoint, then "Try it out".
3. Fill in the parameters or the request body and click "Execute".
4. Check the status code and the response body below.

Suggested test order: create a user, list users, get the user by id, update it, delete it, then request the deleted id to confirm the 404.

## Running the tests

With your `.env` configured and the database set up, run from the project root:

```bash
python -m pytest -v
```
It creates a test user, checks every endpoint, and prints PASS or FAIL for each check.
